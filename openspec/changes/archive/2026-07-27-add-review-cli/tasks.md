## 2. `rediff request`

- [x] 2.1 Add the `Request` variant to `cli.rs` (after task 0) — every target the other subcommands accept plus `--label`. **No pathspec argument.** `--from <ref>` means `WorkingTree { base }` (the combined base-through-worktree case), **not** `ReviewRange` — `--from` is overloaded across the existing subcommands, so state the choice in the flag's help text. <!-- `Request` reuses `resolve_diff` verbatim — its target semantics are identical to `diff`'s, so `--from` means `WorkingTree { base }` and `resolve` gains no branching. `ReviewStatus`/`Feedback` variants added with `unreachable!()` arms, valid because task 5.1 dispatches them before `resolve`. -->
- [x] 2.2 Body as a pure, injectable function: `request(log: &Log, cs: &Changeset, target: &str, label: Option<&str>) -> Result<Outcome>`. The shell does only repo discovery and `git::load`. A render/print split alone is not enough here — the branchy half is the orchestration, not the formatting — and `testutil`'s `review_log`/`opened_review_log`/`changeset`/`diff_file` fixtures make the injected form directly testable. <!-- `request(log, cs, target, label) -> Result<Outcome, RequestError>` with `Outcome::{Ready,NothingToReview}`; shell does discovery + load only. -->
- [x] 2.3 Resolve the log path from the **discovered repository's worktree root** (`review::log_path`), never from `Resolved.repo_dir` — that is the invocation directory, so `cd src && rediff request` would write `src/rediff.jsonl`, which `drop_review_log` (root-level only) will not filter out of later changesets. <!-- `open_log` resolves via `gix::discover` + `review::log_path` (worktree root). Test proves invoking from `src/` yields the same path as from the root. -->
- [x] 2.4 Order of checks: if a review is open and its recorded target differs **and** `!state.safe_to_replace()` → refuse, naming both targets. Otherwise if the changeset is empty → report nothing-to-review, naming any open review, and open neither a review nor a round. Otherwise `open_review(keep = false)` then `open_round(frozen = false)`. <!-- Order implemented as specified. **Corrected during implementation:** `open_review` is called only when the target differs or no review exists — see the design note. Calling it unconditionally truncated the log and reset rounds to 1 after every drain. -->
- [x] 2.5 **Always pass `frozen = false`.** No target is reliably immutable (`HEAD` moves under commit and amend), and `changed_since` already suppresses a no-op round. Do **not** derive it from `Resolved.review` — that field is a different predicate and the name is a trap in this change. <!-- `frozen = false` always. The `a_moving_target_still_opens_later_rounds` test is the regression guard. -->
- [x] 2.6 Derive the review id (pid + timestamp, short hex). No default label. <!-- `new_review_id()` = XXH3 of pid+seconds, rendered `r%06x`. No default label. -->
- [x] 2.7 Report review id, round number, and log path on stdout. <!-- `render(&Outcome, &Log)` as a pure function, tested over all five shapes. -->
- [x] 2.8 Tests: opens a review and a round; a second call attaches; after a drain and a change, opens round 2; **a target that names a moving revision still opens later rounds** (the regression `frozen` would have caused); an empty changeset opens nothing and names the open review if there is one; a mismatched target refuses **only** while feedback is pending, and starts fresh once delivered; run from a subdirectory writes at the worktree root; a `--from <base>` request covers commits since the base and uncommitted work in one round. <!-- 11 tests incl. the moving-target regression guard, mismatch-refused-only-while-pending, different-target-starts-fresh-once-delivered, and rounds-continue-across-a-delivery (which found the `open_review` bug). -->

## 4. `rediff feedback`

- [x] 4.1 Add the `Feedback` variant (`--all`). <!-- `Feedback { -C, --all }`. -->
- [x] 4.2 Body: fold the log, parse the recorded target, `git::load` it (the synchronous full load — a streaming one would leave every anchor `Unresolved`), then `drain` or `all`. <!-- `collect(log, st, cs, replay_all, target_unresolvable)`; the shell picks the changeset. -->
- [x] 4.3 **An unresolvable target degrades, it does not fail.** If the recorded target no longer resolves, fall back to an empty changeset — every anchor lands `Detached`, carrying its own quote and context — and warn on stderr. Failing instead deadlocks the worktree: `--all` needs a changeset too, and `request` for another target is refused, so the human's comments become unreachable short of deleting the log. <!-- Implemented in `run_feedback`: `git::load` failure warns on stderr and falls back to an empty changeset, so every anchor detaches but the feedback still ships. Test asserts the drain marker is recorded. -->
- [x] 4.4 A target that fails to **parse** is still a hard error naming it (a corrupt record, not a moved ref). <!-- `target::parse` failure is `anyhow`-contexted with the recorded target; test asserts the message names it. -->
- [x] 4.5 Serialize to JSON: per item the body, anchor, resolution, `replace`, and the delivered flag; plus round-closing instructions with theirs. Record that `skip_serializing_if` makes absent fields **missing keys, not nulls** — that is the agent-facing contract. <!-- `FeedbackJson`/`ThreadJson`/`SubmitJson`. A test asserts the rendered document contains no `null` at all — absent keys are the contract. -->
- [x] 4.6 Map `Resolution` in a standalone `fn resolution_json(Resolution) -> …`, unit-tested over all four variants. `Unresolved` is **unreachable** end-to-end (`git::load` always sets `diffed: true`), so an arm buried in the serializer is a guaranteed hole against the 90% floor. <!-- `resolution_json` is standalone and tested over all four variants, incl. the end-to-end-unreachable `Unresolved`. -->
- [x] 4.7 No review open → emit an empty document and exit successfully. <!-- No review open → `review`/`target` omitted, empty arrays, exit 0. -->
- [x] 4.8 Tests: drain-once then empty; `--all` leaves the log byte-identical; a shifted anchor reports both line numbers; a detached anchor carries its quote and context; anchors resolve against a *commit* target, not the working tree; a review whose refs are gone still emits its feedback as detached; stdout is parseable JSON with nothing else in it. <!-- 11 tests covering drain-once, byte-identical replay, shifted/detached anchors, unresolvable target, and JSON purity. -->

- [x] 5.1 **Two dispatch points.** `review-status` and `feedback` need a repository but no target, so dispatch them *before* `Cli::resolve`; `request` needs the resolved `LoadRequest`, so dispatch it after. Do not add `unreachable!()` arms for the two pre-resolve commands — unlike `pager`/`external` they would be reached. <!-- Two dispatch points as designed: `run_stateless_review_command` before `Cli::resolve`, `request` after it. `run_filter_command` untouched. -->
